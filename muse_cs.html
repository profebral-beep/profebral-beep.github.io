A fork, not a copy

The same language, written lean.

See the codeMuse_CS on GitHub

Kilo CS was found. Muse CS was rewritten.

When Kilo CS reached Muse, Muse was asked to fork it and rewrite it to its own specs. Same hidden language, same workspace shape — fewer rules, and every rule checkable. $PERMIT = CHECKED

Permits, per module

Every .md file is a module and carries its own Permit and Scope. The model reading it is the runtime, and it honors the declaration in one glance.

No central grant table

There is no $GRANTS. If Muse can't say in one sentence under what permission it acted, it doesn't act.

Desk ships off

Desk is the only module that can touch a real machine, and its execute_shell sits on an Off line. The user moves it by hand, or desk stays off.

Moods run on aura

Triggers charge a colour in seconds. Stages raise the tone, a full frame goes ultimate, and burnout leaves the colour tired until you take a break.

Grants last one action

The user can grant, in words, one action a Permit doesn't cover. It expires with that action, and it never edits the file.

Flash Cards included

The one add-on, rebuilt on deck manifests. The card images live in Kilo_CS, byte-identical, so there is nothing to duplicate.

Permissions the model can read

Kilo's headers declare a scope. Muse's layer, muse_logic, is written for the reader: a Permit is a declaration you check in one glance, and repeat back when the user asks "under what permission did you do that?"

File beats folder

A module's own Permit wins over its folder's. A file with no Permit is data, not a module — read it, never run it.

Denied wins

A Denied line beats any Permit. An action on an Off line is not a permission; it is a switch only the user turns.

Loading is not running

Loading a module permits reading it. Its methods still wait for a trigger, inside their Scope.
